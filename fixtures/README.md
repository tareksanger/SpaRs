# Fixture provenance and use

Inputs were authored for this project; MIT licensed with the project. Outputs are computed by official spaCy 3.8.14, Thinc 8.3.13, en_core_web_md 3.8.0. Model resource licenses apply to copied lexical/vector data; see [licenses](../licenses/).

- development.json: 25 inputs used during implementation; development.expected.json records offsets, lexical feature IDs, shared tok2vec, all final annotations and doc vectors. Currency/dash BASE_NORMS fixes were influenced by this set.
- holdout.json: 10 inputs frozen before implementation comparison; exact agreement on first evaluation, no implementation choices were selected from its outputs. It is now a regression gate, not a fresh future holdout.
- regression.json: 9 subsequent stress cases, including long input (640 tokens), Unicode class/lowercase and whitespace cases. Kept separate from frozen sets.
- stages.expected.json: 25 development cases, each embedding mix and each encoder layer for shared/NER tok2vec; parser/NER context IDs, validity masks, scores and selected action indices. Includes pseudo-projective L-pobj||prep decoding.
- tokenizer.expected.json: 4,057 cases, all 1,347 official exceptions and affix compositions plus Unicode, whitespace and URL cases; 14,737 tokens.
- lexical.expected.json: 4,374 cases covering Unicode property range boundaries and lexical flags. Influenced the exported lower mappings and anchored email fix.
- regex.expected.json: 13,059 texts with 52,236 direct regex span comparisons, from the frozen lexical boundary characters in URL/affix/infix contexts.
- hash.expected.json: 30 Thinc uint64 hash/seed cases including maximal uint64.
- vectors.expected.json: 8 exact static rows/availability checks and 6 similarity pairs, including empty and missing-vector identity behavior.

Generators (run from the repository root): `tools/fixtures.py SPLIT`, [tools/stages.py](../tools/stages.py), [tools/tokenizer_fixtures.py](../tools/tokenizer_fixtures.py), [tools/lexical_fixtures.py](../tools/lexical_fixtures.py), and [tools/regex_fixtures.py](../tools/regex_fixtures.py). Expected fixtures are not generated in normal CI; model export is. The generators exist to reproduce the reference, not to redefine expected results during fixes. Numerical tolerance justification is in the [fidelity contract](../docs/VALIDATION.md).

## Expanded evaluation

- `evaluation-v1.json`: 98 original synthetic inputs across 13 categories, including news-style prose, science, commerce, conversation, instructions, narrative, questions, coordination, negation, web text, Unicode, layout, and long inputs. Frozen before the first comparison. The first run exposed the tokenizer contraction-boundary bug, so this set influenced the correction. The discovered exception-ordering issue and correction are described in [implementation status](../docs/PROGRESS.md). Expected annotations cover 5,568 tokens. The `web-07` path example uses a project-relative path; its expected output was regenerated with the pinned official reference when absolute paths were removed. The other 97 cases remain unchanged.
- `tokenizer-boundaries-v1.json`: 24 cases / 120 tokens chosen to check the discovered exception-ordering issue. Covers contractions around hyphens, slashes, dashes, punctuation, and whitespace, including curly apostrophes. These are development regressions, not a holdout.
- `unseen-v1.json`: 24 new cases / 306 tokens authored and frozen after the tokenizer correction. The first comparison passed without further runtime changes. It is now a regression suite and cannot support a future claim about unseen inputs.

All three input sets are original project-authored examples under the project MIT license. They are not sampled news articles or a representative accuracy benchmark. `tools/evaluation_reference.py` generates their expected files using the pinned official environment, records the input hash, and refuses to overwrite an existing expected file. Expected token annotations, spans, and document vectors are compared; intermediate activations continue to be checked by the separate stage suite.

`checksums.json` freezes the inventory and contents of every JSON fixture. New fixtures need a reviewed checksum entry. Existing hashes and expected values must not change just to make an implementation pass. See the [quality process](../docs/QUALITY.md).

## Dependency traversal

`traversal-v1.expected.json` records official spaCy 3.8.14 children, ancestors, subtree order, and containing sentence for 5,568 tokens across the 98 existing evaluation documents. It reuses project-authored MIT-licensed input text and influenced traversal implementation; it is a regression suite, not an untouched comparison set. `tools/traversal_reference.py` records the input hash, verifies regenerated dependency heads against the frozen input, and refuses to overwrite an output file. To reproduce it after reference setup, run `.venv/bin/python tools/traversal_reference.py fixtures/evaluation-v1.expected.json target/reports/traversal-regenerated.json` and compare that file with the frozen fixture. Rust unit tests separately cover crossing dependencies, missing annotations, cycles, and long chains.

## Dependency matching

`dependency-match-v1.expected.json` contains six project-authored cases under the MIT license: parsed English, multiple sentences, Unicode, empty input, a constructed crossing-dependency tree, and morphology normalization. Each case applies 52 rule additions covering all 20 official relationship operators, seven token attributes (all except `lower`, which has its own fixture below), duplicate patterns, repeated token bindings, and stable result ordering. These cases influenced the initial implementation and are regression evidence, not a linguistic accuracy benchmark. `tools/dependency_match_reference.py` obtains expected matches from pinned spaCy 3.8.14, records its source checksum, and refuses to overwrite output. CI regenerates this fixture and compares it with the frozen expectations.

`dependency-match-regressions-v1.expected.json` adds separate source-review regressions for empty and duplicate morphology, POS-field normalization, conjunctive conditions, and selective dependency-tree ordering. It is generated with `tools/dependency_match_reference.py --regressions OUTPUT`. The original dependency matcher fixture remains unchanged. Both fixtures influenced implementation and are regenerated in CI.

`dependency-match-lower-v1.expected.json` contains 4 project-authored MIT cases, 43 tokens, 160 rule registrations and 223 ordered matches for the `lower` attribute from pinned spaCy 3.8.14 and Python Unicode 15.0.0 data. Cases cover a constructed Unicode word list, a constructed dependency tree, a parsed `en_core_web_md` 3.8.0 document and empty input. Patterns cover equality, `IN`, `NOT_IN`, empty sets, conjunction with `text`, dependency links and a precedence relation. Inputs exercise Greek final sigma, combining marks, dotted capital I, capital sharp S, Deseret, the Kelvin sign, the `ﬀ` ligature, titlecase `ǅ`, digits, emoji, U+1C89 (unassigned in Unicode 15.0.0 but lowercased by later Unicode versions), tokens whose norm differs from their lowercase text (`Gon`/`na` in `Gonna`), and uppercase equality and set values that must not match. Generate with `.venv/bin/python tools/dependency_match_reference.py --lower OUTPUT`; the generator requires Python Unicode 15.0.0 data. Acceptance regenerates and compares this fixture without modifying the checked-in expectations. These cases influenced the shared LOWER implementation and are regression evidence.

`dependency-match-flags-v1.expected.json` contains 3 project-authored MIT cases, 65 tokens, 42 rule registrations and 376 ordered matches for the lexical flag attributes `is_alpha`, `is_digit`, `is_space`, `is_punct` and `like_num` from pinned spaCy 3.8.14 with the `en_core_web_md` 3.8.0 vocabulary and Python Unicode 15.0.0 data. Cases cover a constructed word list, a parsed document and empty input. Each flag is tested with both `true` and `false`, plus conjunctions of two flags, a conjunction with `lower` and a dependency link. Inputs exercise Arabic-Indic and superscript digits, Roman numerals, vulgar fractions, Unicode punctuation categories, currency and math symbols, non-breaking space, newline, NEL and the U+001C separator, combining marks, emoji, multi-character punctuation, signed (`±`, `~`, doubled `-`), grouped and fractional numbers, ordinals including `3th` and `3RD`, a bare `st`, and English number and ordinal words that only the English `LIKE_NUM` accepts. Generate with `.venv/bin/python tools/dependency_match_reference.py --flags OUTPUT`. Acceptance regenerates and compares this fixture without modifying the checked-in expectations. These cases influenced the lexical flag implementation and are regression evidence.

`dependency-match-more-flags-v1.expected.json` covers the twelve other lexical flags (`is_lower`, `is_upper`, `is_title`, `is_ascii`, `is_currency`, `is_stop`, `is_bracket`, `is_quote`, `is_left_punct`, `is_right_punct`, `like_url` and `like_email`): 3 project-authored MIT cases, 98 tokens, 90 rule registrations and 1,209 ordered matches from pinned spaCy 3.8.14 with the `en_core_web_md` 3.8.0 vocabulary and Python Unicode 15.0.0 data. Inputs exercise every case pattern (including titlecase `ǅ`, Greek and mixed letters and digits), currency symbols versus currency codes, English stop words in every capitalization (including curly-apostrophe contractions and a Kelvin-sign spelling that lowercases to a stop word), letters such as `ª` that Unicode treats as lowercase without being ordinary lowercase letters, numbers and an IP address that reach the URL pattern, every bracket and quote spelling in spaCy's lists (including the two-character ` `` ` and `''` and the low and reversed quotes), and URL and email lookalikes. `dependency-match-length-v1.expected.json` contains 3 project-authored MIT cases, 28 tokens, 96 rule registrations and 321 ordered matches for the `length` attribute from pinned spaCy 3.8.14 and Python Unicode 15.0.0 data. Cases cover a constructed word list, a parsed `en_core_web_md` 3.8.0 document and empty input. ## Exact-text phrase matching

`phrase-match-v1.expected.json` freezes spaCy 3.8.14 / preshed 3.0.13 output for 19 development cases, 529 lifecycle states and 14,835 ordered matches. `phrase-match-holdout-v1.expected.json` contains 24 separately seeded comparison cases, 720 states and 17,084 ordered matches. The comparison set was frozen before native implementation and first executed after the initial trie was implemented; both sets are now regression data. Inputs are synthetic project-authored token sequences. Expected outputs come only from the official reference generator, not the Rust implementation.

`.venv/bin/python tools/phrase_match_reference.py OUTPUT` regenerates development expectations; add `--holdout` for the reserved comparison set. Existing outputs are never overwritten. `tools/check_reference.py` regenerates both in temporary storage during acceptance. Source hashes are checked against `reference/source-lock.json` and the additional preshed inventory in `reference/phrase-source-lock.json`. The generator includes ORTH/TEXT alias and unsupported annotation/invalid-attribute probes; these record future scope, not native support for those attributes. All native lifecycle states compare exact ordered output, registration counts and membership; empty inputs, Unicode, whitespace tokens, shared-prefix removal, reserved labels, hash-table growth and tombstones are included.

`phrase-match-edges-v1.expected.json` adds one explicit sentence-boundary case and two Python error-state probes (a valid pattern surviving a later annotation error, and a rule registered before rejecting a single Doc supplied as the collection). Generate it with `--edges`. Native testing executes the sentence-boundary case; unsupported Python input forms remain reference evidence for the documented Rust boundary.

`phrase-match-lower-v1.expected.json` adds 4 project-authored synthetic cases (MIT), 24 lifecycle states and 351 ordered matches from pinned spaCy 3.8.14 / preshed 3.0.13. These cases influenced LOWER implementation and are regression evidence. They cover case variants, Greek final sigma, combining marks, dotted I, sharp S, supplementary Unicode characters, normalization distinctions, overlap and rule lifecycle. `tools/phrase_lower_reference.py --check` checks this fixture and `crates/spars/src/unicode_lower.json` against freshly generated data; generation refuses to overwrite existing files. The resource contains Python Unicode 15.0.0 lowercase mappings and character ranges and retains the [Unicode notice](../licenses/Unicode.txt). The fixture records the pinned matcher and lexical source hashes.
